# سُحُب التقنية | so7ob — المنصة التفاعلية

> **تُمطِرُ حلولًا ذكية.**

منصة **سُحُب التقنية (so7ob)** التفاعلية — موقع تعريفي ثنائي اللغة + حسابات مستخدمين + بوابة عملاء + لوحة إدارة + محرر صفحات يعمل على قاعدة البيانات، مبنية على الموقع التعريفي الأصلي دون تغيير هويته.

## ما تحويه المنصة

### الموقع العام (كما كان + تحسينات)
| الصفحة | المسار (عربي) | المحتوى |
|---|---|---|
| الرئيسية | `/ar` | واجهة افتتاحية، الخدمات، ما يميز طريقة العمل، أعمال توضيحية، مراحل التنفيذ، أسئلة مختارة، دعوة ختامية |
| من نحن | `/ar/about` | التعريف، الرؤية، الرسالة، القيم، المبادئ |
| الخدمات | `/ar/services` | ست خدمات مفصلة |
| أعمالنا | `/ar/works` | ثلاث حالات توضيحية |
| آلية العمل | `/ar/process` | أربع مراحل وإدارة التغييرات |
| الأسئلة الشائعة | `/ar/faq` | 9 إجابات |
| التواصل | `/ar/contact` | نموذج طلب مشروع بحفظ دائم وحمايات |

**كل صفحة تُدار الآن من محرر الصفحات في لوحة الإدارة** — تعديل المحرر هو المصدر الفعلي للعرض، والنشر يظهر فورًا دون تعديل الكود. لكل صفحة نظير إنجليزي تحت `/en/…` مع RTL/LTR صحيحين.

### المصادقة والحسابات
- تسجيل حساب عملاء (الدور ثابت — لا يمكن اختيار دور إداري)، تحقق بالبريد، دخول/خروج، استعادة كلمة المرور، تغييرها.
- حالات الحساب: بانتظار التحقق / نشط / موقوف — الإيقاف يبطل الجلسات فورًا.
- كلمات المرور بتجزئة bcrypt، جلسات JWT مع سجل جلسات في قاعدة البيانات (إبطال فوري)، قفل محاولات الدخول الفاشلة، رموز أحادية الاستخدام محدودة المدة.

### بوابة العميل `/[locale]/account`
لوحة ملخص بمؤشرات حقيقية، طلباتي ومتابعة الحالة، إنشاء طلب بمسودة خادمية (لا LocalStorage)، محادثة مع المرفقات والردود، الإشعارات، الملف الشخصي، الأمان والجلسات، وربط الطلبات القديمة عبر تحقق بالبريد.

### لوحة الإدارة `/[locale]/admin`
مؤشرات تشغيلية من بيانات حقيقية، المستخدمون والأدوار والدعوات، الطلبات (بحث/تصفية/تعيين/حالات/ردود/ملاحظات داخلية/أرشفة/إجراءات جماعية)، الاستفسارات، محرر الصفحات، مكتبة الوسائط، القوائم، إعدادات الموقع، سجل التدقيق، صندوق صادر البريد.

### محرر الصفحات
مكتبة 27 نوع كتل، معاينة مباشرة، لوحة خصائص، سحب وإفلات، تراجع/إعادة، حفظ تلقائي مع كشف تعارض، نشر بصلاحية مستقلة، إصدارات واستعادة، معاينة أجهزة (كمبيوتر/تابلت/جوال)، منتقي وسائط.

## التقنيات وسبب اختيارها

- **Next.js 16 (App Router) + TypeScript**.
- **Tailwind CSS 4 + shadcn/ui** بنظام التصميم الأصلي نفسه.
- **Prisma + SQLite** مع ترحيلات قابلة للمراجعة (`prisma/migrations`) — عند الانتقال لقاعدة أقوى: نفّذ ترحيلًا فعليًا للمخطط والبيانات (تغيير `provider` وحده لا ينقل شيئًا).
- **next-auth v4** (المكتبة المثبتة أصلًا؛ تم التحقق عمليًا من توافقها مع Next 16) مع bcryptjs.
- **zod** للتحقق الخادمي من كتل المحتوى — لا يُنفَّذ أي JavaScript/JSX/MDX قادم من محتوى المستخدم.
- **@dnd-kit** لترتيب الكتل في المحرر.
- **Vitest** لاختبارات التحقق وحد المعدل وتكافؤ الترجمات والواجهة.

## التشغيل المحلي

المتطلبات: [Bun](https://bun.sh).

```bash
git clone https://github.com/so7ob/Website.git && cd Website
bun install
cp .env.example .env          # ثم عدّل AUTH_SECRET (openssl rand -hex 32)
bun run db:migrate            # ترحيلات قابلة للمراجعة
bun run db:seed               # بذرة المحتوى (قابلة لإعادة التشغيل بأمان)
bun run admin:create -- --email admin@example.com --password "StrongPass123"
bun run dev                   # http://localhost:3000
```

> بذرة المحتوى تنقل صفحات الموقع الثابتة إلى قاعدة البيانات مرة واحدة، وتتخطى أي صفحة عدّلها محرر — إعادة تشغيلها لا يكرر الصفحات ولا يكتب فوق تعديلات المحرر.

## إعدادات البريد

- **وضع التطوير (افتراضي)**: `EMAIL_DEV_MODE=true` — تُسجل الرسائل في صندوق صادر داخلي (لوحة الإدارة ← صندوق الصادر) دون إرسال فعلي، وتظهر روابط التحقق/الاستعادة في الاستجابة للتطوير المحلي.
- **الإرسال الفعلي**: عبّئ `SMTP_HOST/PORT/USER/PASSWORD/FROM` واجعل `EMAIL_DEV_MODE=false`.
- غياب الإعداد لا يمنع الحفظ ولا يحاكي نجاحًا — حالة كل رسالة مسجلة.

## روابط المتابعة (تتبع الطلبات والاستفسارات)

عند إرسال طلب أو استفسار تُصدر المنصة **رابط متابعة** يظهر فورًا في شاشة النجاح («فتح المتابعة» / «نسخ الرابط») ويُرسل نسخة منه إلى بريد البطاقة (best-effort — فشل البريد لا يعيق النجاح). في وضع التطوير تُسجَّل الرسالة في صندوق الصادر.

### الأوضاع الأربعة (لكل نوع بطاقة)

| الوضع | حامل الرابط يطّلع | حامل الرابط يرد | مالك الحساب يرد |
|---|---|---|---|
| `login_required` (افتراضي الترحيل) | ✗ | ✗ | ✓ |
| `link_view` | ✓ | ✗ | ✓ |
| `link_reply` | ✓ | ✓ | ✓ |
| `link_view_login_reply` | ✓ | ✗ | ✓ |

**أولوية السياسة** (تُحسب لحظيًا عند كل عرض/رد/تنزيل — لا وقت الإنشاء):
1. **فرض تسجيل الدخول** على مستوى المنصة (الإعدادات ← سياسة روابط المتابعة) — يتغلب على كل شيء.
2. **استثناء البطاقة** (من لوحة تفاصيل الطلب/الاستفسار).
3. **وضع النوع** الافتراضي.

لوحة الطاقم تعرض «السياسة الفعلية» و«مصدرها» لإزالة غموض الوراثة.

### الضمانات الأمنية

- الرمز الخام 32 بايت عشوائي — **يُعرض مرة واحدة** (شاشة النجاح أو التجديد) ولا يُخزن إلا بصمته sha256.
- الرابط قابل لإعادة الاستخدام حتى الانتهاء/الإلغاء؛ جلسة الرابط كوكي `HttpOnly` موقّعة HMAC لعمر 12 ساعة.
- صفحة المتابعة: `noindex` + `no-store` + `Referrer-Policy: no-referrer`، مع حد معدل على تبادل الرمز ومنشأ صارم.
- رد الزائر يُسجل كـ«صاحب رابط المتابعة» مع منع تكرار تطابق خلال دقيقتين؛ البطاقة المغلقة توقف الرد بكل القنوات.
- تنزيل المرفقات عبر الرابط يتطلب: سياسة تسمح بالاطلاع + الرابط فعّال + المرفق على رسالة علنية (الملاحظات الداخلية مستثناة دائمًا) — ويُدوَّن في التدقيق.
- إلغاء الرابط من الطاقم يسري فورًا حتى على الجلسات المشتقة، ولا يُلغي ملكية الحساب للبطاقة.
- إشعار العميل برد الفريق يُرسل لبريد البطاقة **حتى بلا حساب مرتبط**، ورابطه الآمن لا يُحيي رابطًا ملغى أبدًا.
- كل عمليات الإصدار/التجديد/الإلغاء/تغيير السياسة/تنزيل المرفق مدوَّنة في AuditLog بلا أسرار.

## إدارة المحتوى

1. سجّل الدخول كمدير → لوحة الإدارة ← الصفحات.
2. أنشئ صفحة جديدة أو حرّر صفحة قائمة (العربية والإنجليزية تبويبان منفصلان).
3. أضف كتلًا من المكتبة، عدّل الخصائص، رتّب بالسحب، عاين الأجهزة.
4. انشر (صلاحية مستقلة عن التحرير) — التغيير يظهر فورًا للزوار.
5. الإصدارات: كل نشر يحفظ إصدارًا؛ الاستعادة تعيده مسودة ثم القرار لك.

**الفصل المعمول به**: ترجمات واجهة النظام (أزرار/رسائل/نموذج) في `src/content/`؛ المحتوى التحريري للصفحات في قاعدة البيانات ويُدار من المحرر.

## الأدوار والصلاحيات

| الدور | النطاق |
|---|---|
| مدير النظام | كل الصلاحيات |
| مدير العمليات | العملاء والطلبات والاستفسارات والتوزيع والتدقيق |
| موظف الدعم | الطلبات والاستفسارات والردود وتغيير الحالات |
| محرر المحتوى | مسودات الصفحات والوسائط والقوائم (النشر بصلاحية مستقلة) |
| العميل | حسابه وطلباته ومحادثاته ومرفقاته فقط |

التحقق يتم في الخادم لكل عملية (API والمسارات والتنزيلات). الملاحظات الداخلية لا تصل للعميل (استبعاد في الاستعلام نفسه). تعليق/تخفيض آخر مدير نظام نشط مرفوض.

- الأعمال المعروضة توضيحية ومعلنة كذلك.
